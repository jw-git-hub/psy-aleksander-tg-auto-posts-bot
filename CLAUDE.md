## Архитектура
- **post_bot.py** — парсинг источников, рерайт, публикация в канал
- Источники контента: 31 интернет-источник (RSS, сайты, блоги по психологии)
- Рерайт через `claude -p` — переписываем статью в формате канала от лица Александра Красногора
- Конфиг: `config.json` (секреты, НЕ коммитить)
- Трекер опубликованных тем: `posted-topics.json`
- Расписание: cron (сервер в UTC, время Бангкока = UTC+7)
- **publishers/** — абстракция публикации: TelegramPublisher (обязательный), FacebookPublisher и InstagramPublisher через Graph API v21.0.
- FB/IG — best-effort: их ошибки не влияют на дедуп (`posted-topics.json` обновляется только при успехе Telegram). Если токены FB/IG не заданы — каналы пропускаются без ошибок.

## Ключевые правила
- **Тон постов**: экспертный, тёплый, без менторства. От первого лица (Александр Красногор). Практика + эмпатия. Честно о сложном, без сахара.
- **Формат поста**: сначала sendPhoto (картинка из источника), затем отдельно sendMessage (текст). Два отдельных сообщения — это увеличивает лимит символов для текста. Картинку скачиваем от источника, не генерируем.
- **Дедупликация (строго!)**: 4 уровня проверки. L1 URL exact match → L2 Jaccard заголовков (порог 0.35) → L3 entity fingerprint через containment (пересечение / длина меньшего множества, порог 0.6) → L4 семантическая проверка заголовка через Claude Haiku (последние 40 заголовков) + MinHash рерайтнутого текста (порог 0.30). Дубли — критический баг, не допускать.
- **Циклическая ротация**: после публикации всех 80 тем начинается цикл 2. В cycle>=2 передаются excerpts прошлых постов для avoid-repeat в промпте. Цикл хранится в posted-topics.json ("cycle" поле).
- **Telegram 429**: итеративный retry (макс 3 попытки) с ожиданием retry_after
- **Источники**: 31 интернет-источник по психологии отношений, семейной терапии, практической психологии. Берём реальные статьи, рерайтим через Claude.
- **Расписание**: 2 раза в день — 10:00 и 18:00 по Бангкоку (UTC+7). Сервер в UTC: 03:00 и 11:00.
